# ADR-0021: Self-signed CA for Registry TLS

**Status:** Accepted  
**Date:** 2026-05-11

## Context

The Phase B registry requires TLS so that containerd on all nodes and Docker on the laptop can push/pull without the `insecure-registries` workaround used in Phase A.

Two approaches were considered:

1. **cert-manager** — deploy cert-manager into k3s, issue a self-signed or ACME cert via a `Certificate` resource
2. **Local CA generated offline** — generate a CA key + cert once on the laptop, sign a server cert, distribute the CA to all nodes and the laptop

The registry must be reachable before cert-manager itself would be deployed (chicken-and-egg), and the cluster has no public DNS name for ACME/Let's Encrypt.

## Decision

Use a **local self-signed CA** generated by `gen-registry-certs.sh` (openssl).

- CA key and cert live in `registry-certs/` (gitignored) on the laptop
- Server cert SAN includes the node hostname (`rk1-node1`) and its static IP (`192.168.1.11`)
- CA cert is distributed to all nodes via `install-ca.sh` (system trust store + containerd mirror config)
- Laptop Docker trust is automated in `setup-registry.sh`
- CA valid 3650 days; server cert valid 825 days (Apple/browser limit, respected for consistency)

## Consequences

**Positive:**
- No additional cluster components needed before the registry is up
- Works offline and on a LAN without public DNS
- CA is reusable: adding a new SAN to the server cert (e.g. a MetalLB VIP) only requires regenerating `registry.crt`, not the CA
- Fully automated by `setup-registry.sh`

**Negative:**
- CA and key material are stored on the laptop; if lost, all node trust must be re-established
- Certificate rotation is manual (825-day window is ~2.25 years; add a calendar reminder)
- Nodes added later need `install-ca.sh` run against them before they can pull from the registry

## Notes

When a MetalLB VIP is assigned to the registry (Phase B5), add the VIP to `REG_SAN_IP` in `bootstrap-config.kv` and rerun `gen-registry-certs.sh --certs-only`. The CA stays the same; only the server cert changes. Re-create the `registry-tls` Secret and roll the registry pod.
